# Intent

Turn a desired outcome into a falsifiable hypothesis before choosing or building more than necessary. Read the project instructions, available evidence and any previous observation or resolution. The project contract supplies paths, terminology and policies; use [the intent template](assets/intent-template.md) when it does not provide its own format.

1. Separate the desired outcome, existing evidence, assumptions and proposed intervention. If evidence is absent, say so; an Intent may begin as a hypothesis.
2. State the affected population and observable behavior or result. Compare plausible interventions when the choice remains open, then record the selected scope and non-goals.
3. Specify the metric calculation, unit, observation window, target, baseline availability, guardrail and eligible population. Include numerator and denominator for ratios; define aggregation and percentile rules when applicable. Distinguish percentage points from relative improvement. Choose the target before observation and never adjust it after seeing results.
4. Write the Intent to the project-defined location. If none exists, propose `artifacts/<intent-id>/intent.md`. Preserve links to source evidence and prior Intent outcomes.
5. Present the draft for human confirmation. Record confirmation only from an actual reply; confirmation does not authorize a later release decision.

## Output and completion
Use `unknown` or `not measured` when evidence is missing. A complete draft lets another practitioner calculate the metric and judge every guardrail. Report the output path and unresolved assumptions.

Example: simplifying one approval step may increase requests completed within two business days while keeping the rejection-error rate below its threshold. Faster completion alone does not establish user satisfaction.
